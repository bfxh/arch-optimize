# 重构原则详细说明

## 原则一：禁止自作聪明引用旧项目

### 规则

每次重构新项目，**绝不**自动引用用户的旧项目。即使用户保存了旧项目：

- 不自动导入旧项目代码
- 不自动复制旧项目结构
- 不自动沿用旧项目配置
- 不自动"借鉴"旧项目实现

### 例外

用户**明确**说"参考之前的 xxx 部分"时，可以引用用户指定的部分。但必须：
1. 仅引用指定部分
2. 记录引用了什么
3. 确认引用部分没有带入旧问题

### 理由

用户重构是因为对旧项目不满意。自动引用旧项目 = 带入不满意的因素 = 重构无意义。

## 原则二：主动复盘与询问

### 流程

1. **搜索历史**：检查 memory 中是否有该项目的过往记录
2. **主动询问**：
   - "你要不要看看之前是怎么做的？"
   - "之前哪里不满意？"
   - "这次想改进什么？"
3. **记录原因**：用户因为不满意才会重构 → 记录不满意的具体点
4. **展示证据**：如果之前有照片/截图 → 直接发给用户看

### 关键点

- 用户说"不满意"时 → **追问具体原因**，不满足于模糊表述
- 有历史素材时 → **主动展示**，不等用户要求
- 记录要**具体**：不是"建模不好"，而是"树木像拼积木，纹理差"

### 理由

用户可能不会主动说不满意的原因。如果不问，就会重复犯同样的错误。

## 原则三：明确审美与质量底线

### 用户明确讨厌的行为

| 禁止行为 | 严重程度 | 正确做法 |
|---------|---------|---------|
| 用低模球体代替人物 | 极度讨厌 | 真实建模或程序化生成 |
| 树木像拼积木、纹理差 | 极度讨厌 | 物理规则驱动的树木生成 |
| 拿一个球说这是人物 | 极度讨厌 | 最低限度也要有正确拓扑 |
| "指鹿为马"式识别错误 | 极度讨厌 | 如实报告，不虚构 |
| 声称存在但不展示 | 讨厌 | 实际展示内容 |

### 质量底线公式

```
质量底线 = max(用户明确要求, 领域最佳实践, 真实性标准)
```

优先级：
1. **真实性标准**（最高）：物理规则驱动 > 贴图拼接 > 低模占位
2. **用户明确要求**：用户说的就是底线
3. **领域最佳实践**：行业最佳实践作为参考

### 宁可不做，不可做差

如果做不到真实效果：
- **先告知用户**当前能力边界
- **不**用劣质替代冒充成品
- **不**说"这就是最终效果"
- 可以提出替代方案让用户选择

### 理由

用户最讨厌的是"指鹿为马"——明明做得不好却说好。诚实地告知能力边界，比用劣质替代冒充成品要好得多。
