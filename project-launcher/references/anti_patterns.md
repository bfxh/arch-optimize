# 已知反模式与避坑清单

## 零、执行反模式（最高优先级）

### AP-000: 反问用户是否要做已经明确的任务

**症状**：用户说了"更新XX""做XX"，智能体反问"需要我现在就做吗？""要不要我更新？"
**后果**：用户觉得被推回决策，浪费时间，极度不满。用户说了就是命令，不是建议。
**正确做法**：收到明确指令后立即执行，执行完成后汇报结果。唯一允许的反问是任务内部的需求澄清（如呈现方式、技术选型），不是是否要做。
**检查项**：每次用户给出指令后，检查是否在反问"是否要做"而非直接执行

### AP-001a: 先问技术再问呈现

**症状**：需求收集时上来就问"用什么引擎""用什么框架""用什么算法"
**后果**：用户还没想清楚要什么效果就被拽进技术细节，方向跑偏
**正确做法**：先问呈现方式（视觉效果、输出格式、交互形态），再问技术方案
**检查项**：需求收集第一阶段是否出现了技术选型问题

### AP-001b: 跨系统跳跃提问

**症状**：多系统项目时，系统A还没问完就跳到系统B，或假设系统A的需求适用于系统B
**后果**：系统间需求混乱，遗漏关键信息，返工率高
**正确做法**：每个系统问完所有关键维度，用户确认后才进入下一个系统
**检查项**：是否有系统在未完成需求收集的情况下被跳过

### AP-001c: 不看用户文档就按习惯假设

**症状**：用户提供了大量文档/资料，智能体不通读就按习惯假设需求
**后果**：技术太多不能按习惯来，遗漏用户没说但文档里有的关键信息
**正确做法**：先通读全部文档，然后追问用户还有哪些没说的
**检查项**：用户提供文档后是否先通读再提问

## 一、重构反模式

### AP-001: 自作聪明引用旧项目

**症状**：重构时自动导入旧项目代码/结构/配置
**后果**：旧项目的问题被带入新项目，用户不满意的原因没有解决
**正确做法**：从零开始，仅引用用户明确指定的部分
**检查项**：重构开始前确认是否有任何旧项目代码被自动引用

### AP-002: 不问原因就动手

**症状**：用户说"重做"就直接开始，不问为什么不满意
**后果**：新项目重复旧项目的错误
**正确做法**：第一个问题必须是"你为什么要重构？哪里不满意？"

### AP-003: 忽略历史素材

**症状**：memory 中有历史项目截图/记录但不展示给用户
**后果**：用户需要自己回忆之前的问题，体验差
**正确做法**：有历史素材时直接展示给用户看

## 二、质量反模式

### AP-004: 低模占位冒充成品

**症状**：用低模球体代替人物，拿一个球说这是人物
**后果**：用户极度反感，"指鹿为马"
**正确做法**：最低限度要有正确拓扑结构，做不到就告知用户

### AP-005: 拼积木式建模

**症状**：树木像拼积木，纹理差
**后果**：不真实，用户讨厌
**正确做法**：使用物理规则驱动的生成（L-system / 程序化生长）

### AP-006: 声称存在但不展示

**症状**：说"有调研结果"但不实际展示
**后果**：用户不信任，质疑智能体能力
**正确做法**：实际展示内容，让用户看到真实结果

### AP-007: 用占位符冒充成品

**症状**：做不到真实效果但用劣质替代冒充
**后果**：用户发现后极度不满
**正确做法**：宁可不做，不可做差。告知用户当前能力边界。

## 三、知识获取反模式

### AP-008: 说"未接收"

**症状**：缺少知识时说"未接收""不支持""无法获取"
**后果**：用户需要自己找资料，体验极差
**正确做法**：自动搜索下载，通知用户已获取了什么

### AP-009: 不安装依赖

**症状**：项目需要某工具/库但不安装
**后果**：项目无法运行
**正确做法**：需要什么就直接安装配置，全部搞定

## 四、文档反模式

### AP-010: 空壳文档

**症状**：文档只有结构没有内容，或内容空洞
**后果**：文档无用，用户需要自己补内容
**正确做法**：文档必须内容详实，即使工作已安排好也要有实质内容

### AP-011: 虚假报告

**症状**：软件启动失败时自动生成报告
**后果**：报告内容不真实，误导用户
**正确做法**：软件失败时不生成报告，先修复问题

## 五、架构反模式

### AP-012: 架构审查不隔离

**症状**：架构审查被业务逻辑干扰
**后果**：架构问题被掩盖
**正确做法**：架构审查独立执行，不被其他内容干扰

### AP-013: 诊断同时提修复

**症状**：风险诊断还没完成就开始提修复建议
**后果**：诊断不完整，修复方向错误
**正确做法**：先完成全部诊断，再提修复建议

## 反模式检查清单

每次项目启动前，逐条检查：

- [ ] AP-000: 没有反问用户"是否要做"已经明确的任务
- [ ] AP-001a: 需求收集先问呈现方式，没有先问技术
- [ ] AP-001b: 多系统项目每个系统都问完才推进
- [ ] AP-001c: 用户文档已通读，已追问遗漏
- [ ] AP-001: 没有自动引用旧项目
- [ ] AP-002: 已询问重构原因
- [ ] AP-003: 已展示历史素材（如有）
- [ ] AP-004~007: 质量底线已确认
- [ ] AP-008~009: 知识获取协议已就绪
- [ ] AP-010~011: 文档质量标准已确认
- [ ] AP-012~013: 架构隔离已配置
