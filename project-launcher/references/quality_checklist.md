# 质量检查清单

## 项目启动前检查

### 需求检查
- [ ] 需求已收集并经用户确认
- [ ] 重构项目已记录不满意原因
- [ ] 历史素材已展示（如有）
- [ ] 质量底线已从 `config/quality_standards.json` 加载

### 技能激活检查
- [ ] `skill_index.json` 已读取
- [ ] 根据项目类型激活了正确的技能组合
- [ ] req-skill 已首先执行
- [ ] arch-skill 标记为隔离执行

### 知识检查
- [ ] `infrastructure/<type>/` 目录已检查
- [ ] 知识缺口已识别
- [ ] 缺失知识已自动获取（或正在获取）
- [ ] `knowledge/sources.json` 已更新

### 基础设施检查
- [ ] 项目目录结构已创建（文件夹形式，非单个MD）
- [ ] `infrastructure/_index.json` 已更新
- [ ] 所有文件在用户指定目录（默认 D:\开发）

## 项目执行中检查

### 质量底线检查
- [ ] 没有用低模球体代替人物 (P001)
- [ ] 没有拼积木式建模 (P002)
- [ ] 没有"指鹿为马"式错误 (P003)
- [ ] 没有声称存在但不展示 (P004)
- [ ] 没有用占位符冒充成品 (P005)

### 代码质量检查（软件/游戏项目）
- [ ] 代码语言符合用户偏好（C/C++/Rust 优先）
- [ ] 没有死代码或内存模拟
- [ ] 错误处理完善
- [ ] 没有假软件/死代码

### 架构检查
- [ ] 架构审查独立执行
- [ ] 诊断完成后再提修复
- [ ] 架构报告独立输出

## 项目完成前检查

### 文档检查
- [ ] README.md 内容详实
- [ ] DESIGN.md 包含实际架构设计
- [ ] REQUIREMENTS.md 覆盖所有需求
- [ ] CHANGELOG.md 记录了变更
- [ ] 文档不是空壳

### 反模式检查
- [ ] 逐条检查 `references/anti_patterns.md` 中的 AP-001 到 AP-013
- [ ] 所有检查项通过

### 用户确认检查
- [ ] 项目启动包已展示给用户
- [ ] 用户确认满意
- [ ] 未确认的项已记录待跟进
