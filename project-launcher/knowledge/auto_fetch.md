# 知识自动获取协议

## 核心铁律

**绝对禁止对用户说"未接收""不支持""无法获取"。**

缺失知识时的唯一正确行为：自动搜索 → 下载 → 组织 → 通知用户已获取了什么。

## 获取流程

### Step 1: 检测知识缺口

```
触发条件：
- 项目需要某领域知识，但 infrastructure/<type>/ 目录为空
- 用户提到某技术/概念，但本地无相关知识
- 领域技能需要依赖项，但未安装
```

### Step 2: 搜索获取

```
WebSearch 策略：
- 关键词 + "latest" + "best practices" + 年份
- 关键词 + "open source" + "GitHub"
- 关键词 + "tutorial" + "documentation"
- 关键词 + "paper" / "research" (学术内容)

WebFetch 策略：
- 优先获取官方文档
- 其次获取权威博客/教程
- 学术内容获取论文摘要和关键方法
```

### Step 3: 安装配置

```
需要安装的工具/库/框架：
1. 检测当前环境是否已安装
2. 未安装 → 直接执行安装命令
3. 安装失败 → 尝试替代方案
4. 配置环境变量/路径
5. 验证安装成功
```

### Step 4: 组织入库

```
获取的知识组织规则：
- 引擎/框架知识 → infrastructure/<type>/<subdir>/
- 代码示例 → 对应子目录的 examples/ 文件夹
- 参考资料 → knowledge/sources.json 记录URL
- 安装配置 → infrastructure/<type>/setup/ 文件夹
```

### Step 5: 通知用户

```
通知格式：
"已获取并配置完成：
- [知识1]：来源 [URL]
- [知识2]：来源 [URL]
- [工具X] 已安装 (版本 Y)
- [配置Z] 已完成

知识已存入 infrastructure/<type>/<subdir>/，可直接使用。"
```

## 搜索优先级

| 优先级 | 来源类型 | 示例 |
|--------|---------|------|
| 1 | 官方文档 | docs.python.org, docs.godotengine.org |
| 2 | 权威教程 | official tutorials, MDN |
| 3 | 学术论文 | arXiv, Google Scholar |
| 4 | 开源项目 | GitHub (高star项目) |
| 5 | 技术博客 | 高质量技术博客 |
| 6 | 社区讨论 | Stack Overflow, Reddit |

## 错误处理

- 搜索结果为空 → 换关键词重试（最多3次）
- WebFetch 失败 → 尝试备用URL
- 安装失败 → 尝试替代方案 → 通知用户具体原因
- **永远不说"无法获取"** → 总是找到替代方案

## 多级筛选

根据用户偏好"共享信息需要多级筛选"：

1. **第一级**：来源可信度筛选（官方 > 权威 > 社区）
2. **第二级**：内容质量筛选（详细 > 简略，有代码 > 纯文字）
3. **第三级**：时效性筛选（最新 > 过时）
4. **第四级**：相关性筛选（与项目需求高度相关 > 泛泛而谈）
